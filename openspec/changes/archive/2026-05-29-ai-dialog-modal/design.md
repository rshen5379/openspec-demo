## Context

当前 AI 对话界面为全屏布局（100vh flex column），占据整个浏览器视口。用户打开对话后无法查看页面其他内容，页面空间利用率低。需要将对话框改为弹框形式，使用户可以同时浏览背景页面内容。

## Goals / Non-Goals

**Goals:**
- 将对话框改为固定定位的居中弹框，尺寸为 520×620px（不超过 90vw×80vh）
- 添加遮罩层和关闭机制（点击遮罩、ESC 键、关闭按钮）
- 在页面右下角添加浮动操作按钮（FAB）用于打开弹框
- 缩小弹框内字体和间距，保持紧凑布局
- 为深色/浅色主题新增相关颜色变量

**Non-Goals:**
- 不改变对话功能逻辑（消息收发、SSE 流式响应等）
- 不调整弹框内消息气泡的渲染方式
- 不添加弹框拖拽或缩放功能

## Decisions

1. **弹框定位方式**：使用 `position: fixed; top: 50%; left: 50%; transform: translate(-50%, -50%)` 实现居中，而非 `position: absolute` 方案。理由：fixed 定位不依赖父容器，始终相对视口居中，更可靠。

2. **尺寸策略**：使用 `min(520px, 90vw)` 和 `min(620px, 80vh)` 限制弹框尺寸，兼顾桌面端和移动端。理由：纯固定像素在小屏会溢出，纯百分比在大屏会过大。

3. **打开方式**：右下角圆形浮动按钮（FAB），而非顶部导航按钮或侧边栏滑出。理由：FAB 是对话助手类 UI 的常见模式，位置固定易发现，不干扰页面主要内容布局。

4. **关闭机制**：三种方式并选——点击遮罩、按 ESC 键、点击关闭按钮（✕）。理由：多种关闭途径降低用户被困在弹框中的风险。

5. **主题扩展**：在 themes.js 中新增 overlay、shadow、fabBg、fabHover 四个变量，分别控制遮罩背景色、弹框阴影、FAB 背景色和 hover 色深浅主题各自适配。

## Risks / Trade-offs

- **弹框尺寸固定** → 移动端小屏可能显示空间不足 → 通过 `min(520px, 90vw)` 自适应缓解
- **遮罩层阻断交互** → 用户必须关闭弹框才能操作背景页面 → 这是弹框模式的固有特征，可接受
